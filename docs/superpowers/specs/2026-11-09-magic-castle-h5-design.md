# 魔法城堡试玩广告 H5 最小可执行项目设计

## 意图

把《试玩广告H5-打怪升级卡牌策划方案.md》的核心体验落成一个可以直接试玩、也可以导入 Cocos Creator 继续开发的最小项目：横屏固定战斗区，城堡与主角在画面下方，怪物从上方来袭；玩家点按敌人攻击，击杀获得经验，2/4 级选强化卡，3/5 级进入骰子奖励，5 级切换为华丽版并挑战 Boss，胜利后显示下载 CTA。

交付同时提供一个浏览器预览层，便于在没有安装 Cocos Creator 的环境中验证玩法和表现。预览层使用同一套颜色、文案、等级与奖励规则，方便后续把数值和表现迁移到 Cocos 场景。

## 目标

- 建立可打开的 Cocos Creator 3.x 项目骨架，默认进入 `BattleScene`。
- 建立可双击或通过本地静态服务器打开的 `preview/index.html`。
- 完成约 30～45 秒的最小试玩闭环：开始提示、敌人生成、点按攻击、经验升级、卡牌三选一、骰子奖励、普通版到华丽版进化、Boss、胜利 CTA。
- 使用提供的角色设定板作为角色来源：普通版与华丽版通过裁切显示，避免引入未经确认的外部素材。
- 保持横屏 H5 适配，按钮和敌人点击区域足够大。

## 非目标

- 不实现完整的对象池、资源热更新、音频、真实广告 SDK、支付和下载链接接入。
- 不擅自确定方案中标记为“待确认”的技能数值、骰子点数映射或第三张联动卡；最小项目使用可替换的演示数值。
- 不制作完整 5 种敌人的美术资源；预览使用统一的可爱绘本风格矢量/Canvas 敌人表现，Cocos 代码保留敌人类型字段。

## 约束

- 技术栈：Cocos Creator 3.x、TypeScript、Web Mobile；浏览器预览使用原生 HTML/CSS/Canvas，不引入构建依赖。
- 设计分辨率：1280×720；通过 CSS `aspect-ratio` 与 Canvas resize 保持横屏比例。
- 角色来源：`参考图/角色参考图/设计图终稿.png`，普通版和华丽版按参考图的左右上方区域裁切。
- 核心流程固定为：点按攻击 → 击杀获得经验 → 升级选卡 → 骰子奖励 → 进化 → Boss → 胜利 CTA。
- 试玩控制在 30～45 秒；默认通过降低每只怪物血量和经验阈值保证流程可快速完成。

## 交互与画面

- 开局显示“守护城堡”标题、简短提示和开始按钮；点击开始后战斗自动开始。
- 战斗画面：上方为渐变天空与云层，中后景为城堡，下方中央为角色；敌人从上方随机位置向城门方向下落/移动。
- 点击敌人时显示锁定圈、星光弹道和伤害数字；敌人死亡时掉落经验星尘。
- 顶部显示等级、经验条、击杀数与当前技能徽章；底部显示“点击敌人攻击”的手势提示。
- 升级面板暂停生成与移动，展示三张卡；卡牌点击后关闭面板并恢复战斗。
- 3/5 级的第三张卡是骰子卡；点击后显示短暂骰子动画和奖励结果。
- 达到 4 级后显示一次“魔法进化”过渡，替换为华丽版角色并增加光环/翅膀绘制；5 级生成大号 Boss。
- Boss 被击败后显示胜利页、角色与“立即下载”按钮，按钮先显示演示反馈文本。

## 游戏状态

- `GameState`: `start | battle | levelUp | dice | evolve | boss | victory`。
- 等级从 1 开始，升级节点为 2、3、4、5；每次升级阈值使用演示数组。
- 默认技能为龙卷风；骰子至少解锁花瓣舞、水流冲击、地面火焰、穿透闪电箭中的一个，技能徽章只做视觉反馈。
- 卡牌数据包含 `id/title/description/color/remaining`; 普通卡与骰子奖励共用剩余次数。
- 敌人数据包含 `kind/hp/speed/reward`; Boss 使用单独的 `boss` 类型和大血条。

## 项目结构与职责

```text
cocos-project/
  project.json                 Cocos Creator 项目入口配置
  settings/                    设计分辨率、启动场景、Web 设置
  assets/
    scenes/BattleScene.scene   可编辑场景（或由脚本在运行时生成节点）
    scripts/GameManager.ts     状态机、等级、升级与进化流程
    scripts/BattleManager.ts   敌人生成、点击命中、经验与 Boss
    scripts/UiManager.ts       HUD、卡牌、骰子和 CTA
    textures/character-board.png 角色设定板副本
preview/
  index.html                   浏览器试玩入口
  game.js                      Canvas 绘制、输入与游戏状态机
  style.css                    横屏容器、按钮、卡牌与安全区样式
  character-board.png          角色设定板副本
README.md                      打开 Cocos 项目与运行预览的步骤
```

浏览器预览优先保证无需构建即可运行；Cocos 项目使用相同的状态命名、等级阈值、卡牌数据和角色裁切参数，便于后续将预览表现替换成正式节点与 Prefab。

## 验收标准

- 打开 `preview/index.html` 后能看到横屏战斗场景，开始按钮可点击。
- 点击敌人会造成伤害，敌人会消失并推动经验条；升级面板会在 2/3/4/5 级出现。
- 3 级和 5 级面板含骰子卡，点击后能看到奖励提示并恢复战斗。
- 角色从普通版切换为华丽版，Boss 出现且可被点击击败。
- Boss 击败后出现胜利 CTA，点击下载按钮有可见反馈。
- 关键状态不依赖网络；素材来自工作区或代码绘制。
- `cocos-project` 能被 Cocos Creator 3.x 识别并打开，脚本无明显语法错误。

## Approaches

1. **只做原生 Cocos Creator 项目**：最贴近正式制作，但当前环境没有 Cocos 编辑器，无法即时给出可试玩结果；运行验证完全依赖用户本地编辑器。
2. **Cocos 项目 + 原生 Canvas 预览（采用）**：同时满足可迁移的工程骨架与当场可验证的试玩闭环；代价是需要维护一个轻量预览层，但预览层不引入依赖，后续可逐步替换为 Cocos 节点。
3. **只做浏览器 Demo**：交付速度快，但无法满足用户希望用 Cocos Creator 接手的工程要求，因此不采用。

## 留给实现者的决定

- Cocos 场景先由单一 `BattleScene` 承载，运行时创建 UI 与战斗节点，减少 `.scene` 手工序列化错误。
- 角色板在预览中用 `drawImage` 的 source rect 裁切；Cocos 中保留同一张板图并在脚本中设置 SpriteFrame rect，用户可在编辑器中替换成独立透明 PNG。
- 演示阶段的敌人与技能特效用 Canvas/Cocos Graphics 绘制，避免生成额外图片资源。
